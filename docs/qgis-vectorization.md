# Векторизация топологии порта в QGIS

Инструкция для QGIS 3.x. Промежуточные данные хранить в GeoPackage (`.gpkg`), а не в Shapefile.

## 1. Создать проект

1. Откройте QGIS.
2. Выберите **Проект → Создать**.
3. В правом нижнем углу нажмите на текущую систему координат.
4. Выберите метрическую CRS для территории порта:
   - обычно подходящую зону UTM;
   - либо официальную местную систему координат.
5. Сохраните проект, например `terminal_topology.qgz`.

Важно: CRS должна измерять расстояния в метрах.

## 2. Добавить растровую карту

Выберите:

**Слой → Добавить слой → Добавить растровый слой**

и откройте изображение.

Если оно сразу появилось в правильном месте, растр уже геопривязан — переходите к созданию векторных слоёв.

Если изображение оказалось около координат `(0, 0)` или далеко от ожидаемого места, его нужно геопривязать.

## 3. Геопривязать растр

1. Откройте **Растр → Геопривязка**.
2. Загрузите исходное изображение.
3. Нажмите **Добавить точку**.
4. Укажите заметную точку на растре.
5. Введите её реальные координаты либо выберите точку на уже геопривязанной карте.

Подходящие контрольные точки:

- углы капитальных зданий;
- торцы причальной стенки;
- пересечения железнодорожных путей;
- углы площадки;
- геодезические знаки;
- пересечения дорог.

Добавьте минимум 4 точки, лучше 8–15. Распределяйте их по всей площади изображения, а не только в одном углу.

### Параметры преобразования

Откройте **Параметры трансформации**:

- тип преобразования: **Полиномиальное 1**;
- метод интерполяции: **Билинейный**;
- целевая CRS: CRS проекта;
- формат результата: GeoTIFF;
- включите загрузку результата в QGIS.

Для обычного плана `Полиномиальное 1` обычно достаточно. Для перспективной фотографии может потребоваться `Projective`, но точность будет хуже.

Запустите геопривязку и проверьте остаточные ошибки контрольных точек. Желательно получить ошибку не более 0,5–1 м.

## 4. Создать GeoPackage

Выберите:

**Слой → Создать слой → Новый слой GeoPackage**

Создайте файл:

```text
terminal_topology.gpkg
```

Все последующие слои можно хранить внутри него.

## 5. Создать слои топологии

Создайте следующие слои.

### Суша

- имя: `land`;
- геометрия: `Полигон`;
- поля:
  - `id` — текст;
  - `name` — текст.

### Вода

- имя: `water`;
- геометрия: `Полигон`;
- поля:
  - `id`;
  - `name`.

### Береговая линия

- имя: `shoreline`;
- геометрия: `Линия`;
- поля:
  - `id`;
  - `type`.

### Причальная стенка

- имя: `quay_wall`;
- геометрия: `Линия`;
- поля:
  - `id`;
  - `name`;
  - `height_m` — число;
  - `berth_id` — текст.

### Контейнерные блоки

- имя: `yard_blocks`;
- геометрия: `Полигон`;
- поля:
  - `id`;
  - `name`;
  - `rotation` — прежний ручной азимут оси `bay`; оставлен только для миграционной сверки и не участвует в сборке;
  - `rows`;
  - `bays`;
  - `max_tier`;
  - `row_pitch`;
  - `bay_pitch`.

### Направляющие блоков

- имя: `block_axes`;
- геометрия: `Линия` (`LineString` ровно из двух точек);
- поля:
  - `block_id` — соответствует `yard_blocks.id`.

Первая точка линии — угол слота `row=1, bay=1`, вторая — соседняя вершина блока в положительном направлении оси `bay`. Порядок точек важен: линия одновременно задаёт начало нумерации и направленный угол. Ось `bay` не обязательно совпадает с самой длинной стороной полигона.

При сборке первая точка автоматически сдвигается к центру первой ячейки, который ожидает viewer. Слой `block_origins` после миграции не используется.

### Дороги

- имя: `roads`;
- геометрия: `Линия`;
- поля:
  - `id`;
  - `name`;
  - `width_m`;
  - `direction`.

### Железнодорожные пути

- имя: `railways`;
- геометрия: `Линия`;
- поля:
  - `id`;
  - `name`;
  - `gauge_m`.

### Здания

- имя: `buildings`;
- геометрия: `Полигон`;
- поля:
  - `id`;
  - `name`;
  - `color`.

`id` и `name` обязательны. `color` — текстовое поле с цветом конкретного здания в формате `#RRGGBB`, например `#8B5E3C`. Стиль слоя QGIS сам по себе не попадает в GeoJSON, поэтому цвет необходимо хранить именно в атрибуте. Для всего слоя можно задать одинаковое значение поля по умолчанию, а затем изменить его у отдельных зданий.

### Виртуальные причалы V4

Создайте два слоя в той же CRS, что и проект:

- `berth_points_v4` — геометрия `Точка`, поля `berth_id` и `name`;
- `berth_heading_axes_v4` — геометрия `Линия`, поле `berth_id`.

Каждая точка находится на линии причала в центре виртуальной позиции. Направляющая состоит ровно из двух точек: первая должна совпадать с точкой причала, вторая указывает на нос судна при швартовке правым бортом. Для точного совпадения включите привязку слоя направляющих к вершинам `berth_points_v4`. Длина линии не задаёт длину причала; достаточно 10–30 м.

Идентификаторы `50`, `50-1` и `50-2` считаются независимыми позициями. Связь с физическим причалом по имени или префиксу не вычисляется.

### Портальные краны V4

Создайте слой `portal_cranes_v4` с геометрией `Точка` и полями:

- `id` — уникальный идентификатор;
- `name` — отображаемое имя;
- `model` — марка крана, например `Витязь 45-63` или `DBM 6045`;
- `azimuthDeg` — геодезический азимут стрелы: 0° — север, 90° — восток;
- `scale` — положительный относительный масштаб;
- `color` — цвет в формате `#RRGGBB`.

Точка задаёт центр основания крана. Направление стрелы хранится атрибутом,
отдельная направляющая не требуется.

У всех слоёв должна быть та же CRS, что у проекта.

## 6. Настроить привязку объектов

Откройте:

**Проект → Параметры привязки**

Включите:

- привязку для всех векторизуемых слоёв;
- режим `Вершина и сегмент`;
- допуск около 10 пикселей либо 0,1–0,5 м;
- топологическое редактирование;
- привязку к пересечениям.

Это предотвратит появление щелей между водой, сушей и причальной стенкой.

## 7. Оцифровать береговую линию

1. Выберите слой `shoreline`.
2. Нажмите **Переключить режим редактирования**.
3. Выберите **Добавить линию**.
4. Последовательно ставьте точки вдоль границы вода/суша.
5. Правой кнопкой завершите линию.
6. Заполните атрибуты и сохраните изменения.

Не ставьте точку на каждый пиксель. Добавляйте вершины там, где изменяется направление линии.

Причальную стенку лучше рисовать отдельной линией с более высокой точностью.

## 8. Оцифровать сушу и воду

Для слоя `land`:

1. Включите редактирование.
2. Выберите **Добавить полигон**.
3. Обведите всю территорию суши.
4. Замкните полигон правой кнопкой.

Аналогично создайте полигон `water`.

Вода — **источник заливки** акватории в d3_v3. Без `water.geojson` viewer откатывается к устаревшей эвристике по `shoreline` (может залить сушу). Экспортируйте `data/geojson/water.geojson` (EPSG:32652).

В репозитории может лежать bootstrap-полигон, построенный смещением береговой линии; для продакшена замените его ручной оцифровкой по спутнику/плану.

Вода может быть большим внешним полигоном вокруг причала. Следите, чтобы полигон не перекрывал контейнерные блоки.

## 9. Оцифровать контейнерные блоки

1. Выберите `yard_blocks`.
2. Обведите внешний контур каждого блока.
3. Для прямоугольных блоков используйте инструмент создания прямоугольника.
4. Заполните параметры блока:
   - количество рядов;
   - количество бэев;
   - максимальный ярус;
   - шаг рядов и бэев.

Для точных размеров используйте панель **Дополнительная оцифровка**. Она позволяет задавать длину сегмента и угол с клавиатуры.

Контур блока сам по себе недостаточен: необходимо определить начало и направление нумерации. Для каждого блока нарисуйте в `block_axes` одну линию из двух точек:

1. включите привязку к вершинам `yard_blocks`;
2. первую точку поставьте в угол слота `row=1, bay=1`;
3. вторую точку поставьте в соседнюю вершину той же стороны в направлении `bay=2, bay=3, ...`;
4. завершите линию, не добавляя промежуточных точек, и заполните `block_id`.

Удобно настроить символ линии со стрелкой на последней вершине. Это позволяет визуально проверить направление нумерации.

При сборке `topology.blocks`:

```text
absoluteRotation = degrees(atan2(P2.northing - P1.northing, P2.easting - P1.easting))
rotationDeg = (absoluteRotation - scene_origin.rotationDeg) mod 360
```

Координаты `P1` сдвигаются внутрь блока на половину `bay_pitch` и половину `row_pitch`, потому что `topology.blocks.originX/originY` задают центр ячейки `row=1, bay=1`. Нумерация `row`/`bay` в snapshot — с **1**.

## 10. Оцифровать остальные объекты

Последовательно обведите:

1. причальные стенки;
2. дороги;
3. железнодорожные пути;
4. здания;
5. ворота;
6. технологические и запрещённые зоны.

Дороги удобно хранить осевыми линиями с полем `width_m`. Их ширину затем сформирует 3D-визуализатор.

## 11. Проверить геометрию

Для каждого полигонального слоя выполните:

**Обработка → Панель инструментов → Проверить геометрии**

Также используйте:

- **Проверка корректности**;
- **Исправить геометрии**;
- **Проверка топологии**.

Проверьте:

- незамкнутые полигоны;
- самопересечения;
- дублирующиеся вершины;
- щели между водой и сушей;
- пересечения контейнерных блоков;
- разрывы причальной стенки.

## 12. Упростить сложные линии

Если береговая линия содержит слишком много точек:

1. Откройте **Обработка → Упростить геометрии**.
2. Включите сохранение топологии.
3. Укажите допуск, соответствующий точности растра.

Обычно можно начать с 0,2–0,5 м. Допуск не должен быть меньше реального размера пикселя исходной карты.

Причальную стенку лучше не упрощать либо использовать минимальный допуск.

## 13. Создать локальную систему координат сцены

Выберите контрольную точку `Origin`, например юго-западный угол терминала. Параметры храните в `data/scene_origin.txt`:

```text
crs=EPSG:32652
originEasting=...
originNorthing=...
rotationDeg=38
note=...
```

`rotationDeg` — математический угол (от востока, против часовой) в **локальных** координатах до поворота сцены; после экспорта это направление становится осью +X (горизонталь на плане). Ориентир для Владивостокского терминала: ось `bay` длинных блоков O-1/O-2 (≈ 38° после перевода азимута QGIS).

Координаты сцены вычисляются конвертером `tools/build_topology_from_geojson.py`:

```text
x0 = easting - originEasting
y0 = northing - originNorthing
θ = -rotationDeg
sceneX = x0·cosθ - y0·sinθ
sceneY = x0·sinθ + y0·cosθ
```

Для блоков:

```text
absoluteRotation = degrees(atan2(P2.northing - P1.northing, P2.easting - P1.easting))
block.rotationDeg = (absoluteRotation - scene_origin.rotationDeg) mod 360
```

В данных `sceneY` растёт к «северу» повёрнутой сцены. Canvas viewer при выводе инвертирует экранную ось Y, поэтому верх экрана соответствует большим `sceneY`.

Лучше сохранять исходные геодезические координаты в GeoPackage, а локальные координаты и поворот сцены вычислять при экспорте. Это позволит уточнить origin/`rotationDeg` без повторной векторизации.

## 14. Экспортировать GeoJSON

Для каждого слоя:

1. Нажмите правой кнопкой по слою.
2. Выберите **Экспорт → Сохранить объекты как**.
3. Формат: `GeoJSON`.
4. CRS: исходная метрическая CRS.
5. Кодировка: UTF-8.
6. Включите только необходимые поля.

Пример файлов:

```text
land.geojson
water.geojson
shoreline.geojson
quay_wall.geojson
yard_blocks.geojson
block_axes.geojson
roads.geojson
railways.geojson
buildings.geojson
berth_points_v4.geojson
berth_heading_axes_v4.geojson
portal_cranes_v4.geojson
```

**Вода:** заливка в viewer идёт из `water.geojson` → `site.water` (полигон акватории). `shoreline` — только обводка берега/причала, её **не** замыкают для заливки моря.

**Здания:** `buildings.geojson` загружается сборщиком V4 напрямую в макет `Buildings_geojson`, без записи в `terminal-layout-v4.json`. Экспортируйте поля `id`, `name` и `color`; визуализация использует `color` для заливки и выводит `name` поверх полигона.

**Виртуальные причалы:** экспортируйте оба слоя в `berth_points_v4.geojson` и `berth_heading_axes_v4.geojson`. Сборщик V4 объединяет их в `berths-v4.json`; исходные GeoJSON в макеты 1С не загружаются.

**Портальные краны:** экспортируйте точки в `portal_cranes_v4.geojson` с полями
`id`, `name`, `model`, `azimuthDeg`, `scale`, `color`. Сборщик объединяет их
с ручным `yard-cranes-v4.json` в единый `cranes-v4.json`.

При сборке snapshot:

- направленная ось `bay` и угол первой ячейки — из `block_axes` (join по `block_id` = `id`);
- конвертер вычисляет угол из вектора первой точки ко второй, вычитает `scene_origin.rotationDeg` и сдвигает угол ячейки к центру;
- ручной `yard_blocks.rotation`, если заполнен, используется только для предупреждения о расхождении более чем на 5°;
- сборка останавливается, если линия пропущена, содержит не две точки, не совпадает со стороной полигона или по размерам сетки вероятнее задаёт ось `row`;
- размеры контейнера сохраняются отдельно как `baySize = bay_pitch × 0,94` и `rowSize = row_pitch × 0,88`;
- если минимальная сетка не помещается в соответствующую сторону полигона, сборка останавливается с перечнем блоков и дефицитом размера;
- если полигон больше минимальной сетки, `bayPitch` и `rowPitch` увеличиваются так, чтобы крайние контейнеры касались границ блока, а свободное место равномерно распределялось только между контейнерами;
- `site.water` — вершины полигона воды в локальных метрах.

## 14.1. Запуск `build_topology_from_geojson.py`

Конвертер собирает локальный snapshot из GeoJSON + `scene_origin.txt` и вшивает топологию в stub `d3_v3`.

### Входные файлы

```text
data/scene_origin.txt
data/geojson/shoreline.geojson
data/geojson/water.geojson          # желательно; без него — legacy-заливка по shoreline
data/geojson/yard_blocks.geojson
data/geojson/block_axes.geojson
```

### Команда

Из корня репозитория (`c:\1c\d3`):

```powershell
python tools/build_topology_from_geojson.py
```

Полезные опции:

```powershell
# только JSON, без правки ObjectModule.bsl
python tools/build_topology_from_geojson.py --no-patch-bsl

# другой каталог data /
python tools/build_topology_from_geojson.py --data-dir data
```

Нужен Python 3 (стандартная библиотека, без pip-зависимостей).

### Что перезаписывается

| Файл | Назначение |
|------|------------|
| `data/topology_snapshot.json` | полный snapshot (site + topology + meta) |
| `data/topology_snapshot.bsl.txt` | фрагмент BSL для справки |
| `src/DataProcessors/d3_v3/ObjectModule.bsl` | блок `СгенерироватьДемоСцену` (shoreline, water, blocks) |

После запуска: **обновить конфигурацию БД** в EDT и **полностью закрыть/открыть** форму V3 — HTML/snapshot собираются при создании формы.

### Когда запускать снова

- изменили GeoJSON в QGIS;
- поправили `originEasting` / `originNorthing` / `rotationDeg` в `scene_origin.txt`;
- нужно синхронизировать stub 1С с картой.

Подкрутка горизонтали сцены — правьте `rotationDeg` в `scene_origin.txt` (±2–3°) и снова запускайте скрипт.

## 15. Финальная проверка

Перед передачей данных в 1С:

- наложите векторные слои на растр;
- измерьте длину известного участка причала;
- измерьте размеры нескольких контейнерных блоков;
- проверьте три контрольные точки;
- убедитесь, что все ID уникальны;
- убедитесь, что у каждого здания заполнены `name` и `color` в формате `#RRGGBB`;
- убедитесь, что множества `berth_id` в точках и направляющих совпадают;
- проверьте привязку начала каждой направляющей к соответствующей точке причала и направление на нос при правом борте;
- проверьте направление нумерации рядов и бэев;
- убедитесь, что у каждого `yard_blocks` есть одна двухточечная линия в `block_axes`;
- проверьте, что первая точка каждой линии — угол `row=1,bay=1`, а стрелка направлена в сторону роста `bay`;
- убедитесь, что единицы измерения — метры.

Критически важные объекты — причальная стенка, границы и направляющие блоков — желательно сверить с чертежом или фактическими координатами, а не только с растровым изображением.

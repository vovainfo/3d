# Железная дорога V4

## Контракт исходных данных
- Добавить [`data/geojson/railways_visual_v4.geojson`](data/geojson/railways_visual_v4.geojson): набор `LineString` для всей отображаемой сети, включая пути под составами. Бизнес-идентификатор и имя не обязательны; `gauge_m` и `color` опциональны, по умолчанию 1,52 м и общий цвет рельсов.
- Добавить [`data/geojson/railway_branches_v4.geojson`](data/geojson/railway_branches_v4.geojson): по одному невидимому направленному `LineString` на ветку размещения с обязательными `branch_id` и `name`, опциональными `gauge_m`/`color`. Ветка должна лежать на визуальной сети с допуском 0,5 м. Порядок вершин задаёт начало цепажа и положительное направление; имена вроде `1 выст.` и `0_45` сохраняются как произвольный текст без проверки формата.
- Добавить [`data/trains-v4.json`](data/trains-v4.json) и документированный пример [`docs/trains-v4-example.json`](docs/trains-v4-example.json). Состав содержит `id`, `name`, `branchId`, `offsetM`, `direction: forward|reverse`, опциональный `gapM` (по умолчанию 1 м) и упорядоченный массив `wagons`. `offsetM` — начало занятого составом интервала по ходу оцифровки ветки; вагоны раскладываются к росту цепажа, а `direction: reverse` только разворачивает их на 180°.
- Для вагона задать уникальный `id` без пробелов, `type`, положительный `lengthM` и boolean `loaded`. Известные типы: `фит.пл.`, `пв`, `тер`, `кр`, `реф`, `сетка а/м`, `цистерна`. Неизвестный непустой `type` допустим и рисуется с вопросительным знаком. Вид груза и контейнеры в контракт не входят.

```json
{
  "id": "TRAIN-001",
  "branchId": "1 выст.",
  "offsetM": 25,
  "direction": "forward",
  "wagons": [
    {"id": "W-001", "type": "пв", "lengthM": 13.92, "loaded": true},
    {"id": "W-002", "type": "фит.пл.", "lengthM": 25.8, "loaded": true}
  ]
}
```

## Сборщик и макеты 1С
- Расширить [`tools/build_scene_v4.py`](tools/build_scene_v4.py): подключить три источника, проверить CRS и `LineString` с минимум двумя разными точками, уникальность `branch_id`, ссылки составов, уникальность ID составов/вагонов, конечные числовые значения, типы грузов и контейнерную вместимость.
- По фактическим длинам веток и каталогу типовых размеров вагонов вычислять интервалы составов; отклонять выход корпуса вагона за ветку и пересечение двух составов на одной ветке. Изломы допустимы: каждый вагон получает положение по длине полилинии и касательную в своей центральной точке.
- Формировать производный [`data/railways-v4.json`](data/railways-v4.json) с нормализованными двумя наборами линий, составами и разрешёнными размерами вагонов; включить исходники и производный файл в SHA-256 манифест по существующему паттерну `cranes-v4.json`.
- Добавить макет [`src/DataProcessors/d3_v4/Templates/RailwaysV4_json/Template.txt`](src/DataProcessors/d3_v4/Templates/RailwaysV4_json/Template.txt), зарегистрировать `RailwaysV4_json` в [`src/DataProcessors/d3_v4/d3_v4.mdo`](src/DataProcessors/d3_v4/d3_v4.mdo) и синхронизировать [`SceneManifestV4_json`](src/DataProcessors/d3_v4/Templates/SceneManifestV4_json/Template.txt).

## Сборка сцены и геометрия
- В [`src/DataProcessors/d3_v4/ObjectModule.bsl`](src/DataProcessors/d3_v4/ObjectModule.bsl) читать и сверять новый макет, преобразовывать все вершины через общий `scene_origin` и помещать линии в `topology.railways.visual` и `topology.railways.branches`.
- Добавить интерполяцию по накопленной длине полилинии. Для каждого вагона вычислять центр, касательную/поворот с учётом `direction` и передавать объект сцены `kind: railWagon` с `wagonType`, `trainId`, `branchId`, `loaded`, `size` и цветами.
- Учесть вершины путей и габариты вагонов в `РассчитатьГраницыСцены`; добавить количество веток/составов/вагонов в результат сборки и строку состояния.

## Отрисовка и карточки
- В [`src/DataProcessors/d3_v4/Templates/МакетJS/Template.txt`](src/DataProcessors/d3_v4/Templates/МакетJS/Template.txt) нормализовать новый раздел топологии, но рисовать рельсы только по визуальным полилиниям: две рельсовые нити по сегментам и шпалы с постоянным шагом по накопленной длине. Ветки размещения использовать только при расчёте вагонов, не рисовать и не подписывать.
- Заменить демонстрационную общую логику вагонов на семь известных видов сверху и fallback с вопросительным знаком. Гружёный вагон получает условный груз по типу; пустые вагоны — красный крест.
- Расширить `equipmentBounds`, hit-test, выделение и поиск для `railWagon`. В [`src/DataProcessors/d3_v4/Forms/Форма/Module.bsl`](src/DataProcessors/d3_v4/Forms/Форма/Module.bsl) добавить карточку вагона с составом, веткой, типом, длиной и признаком загрузки.

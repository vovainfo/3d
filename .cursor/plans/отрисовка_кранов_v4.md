# Краны терминала V4

## Контракт данных
- Добавить исходники:
  - [`data/geojson/portal_cranes_v4.geojson`](data/geojson/portal_cranes_v4.geojson) — точки портальных кранов с обязательными атрибутами `id`, `name`, `model`, `azimuthDeg`, `scale`, `color`.
  - [`data/yard-cranes-v4.json`](data/yard-cranes-v4.json) — общий ручной реестр RTG/RMG с `id`, `name`, `type`, `siteId`, `movementAxis`, `positionM`, `color`; для RMG дополнительно обязательный `railInsetM`.
  - Производный [`data/cranes-v4.json`](data/cranes-v4.json) со всеми тремя типами и `schemaVersion: "4.0"`.
- Цвет сделать обязательным для всех кранов в формате `#RRGGBB`; `scale` портального крана — конечное положительное число, допускающее значения меньше и больше 1.
- `azimuthDeg` трактовать как геодезический азимут QGIS: 0° — север, 90° — восток, направление по часовой стрелке. При сборке сцены преобразовывать его с учётом `scene_origin.rotationDeg`; визуальный вектор стрелы должен точно совпадать с этим азимутом.
- `positionM` считать положительным вдоль выбранной оси `bays`/`rows` от угла ячейки 1-1; отрицательные значения и выход корпуса крана за площадку разрешить.
- `railInsetM` применять симметрично: каждый рельс RMG отстоит внутрь от своей поперечной границы площадки на это расстояние. Длина обоих рельсов равна размеру площадки вдоль `movementAxis`; выход крана за концы рельсов разрешить.

## Сборка и проверка
- Расширить [`tools/build_scene_v4.py`](tools/build_scene_v4.py): подключить оба исходника, проверить CRS/Point портальных кранов, уникальность ID по всем типам, обязательные строки, цвет, диапазон азимута, положительный масштаб, существование `siteId`, ось движения и допустимость симметричного `railInsetM` относительно поперечного размера площадки.
- Нормализовать и объединить источники в `cranes-v4.json`, включить исходники и производный файл в SHA-256 `SceneManifestV4_json`, поддержать режим `--check` без записи и синхронизацию нового макета `CranesV4_json`.
- Обновить регистрацию текстового макета в [`src/DataProcessors/d3_v4/d3_v4.mdo`](src/DataProcessors/d3_v4/d3_v4.mdo) и добавить [`src/DataProcessors/d3_v4/Templates/CranesV4_json/Template.txt`](src/DataProcessors/d3_v4/Templates/CranesV4_json/Template.txt).

## Сборка сцены в 1С
- В [`src/DataProcessors/d3_v4/ObjectModule.bsl`](src/DataProcessors/d3_v4/ObjectModule.bsl) читать `CranesV4_json`, сверять его по манифесту и добавлять краны к `scene.objects` вместе с судами.
- При построении площадок сохранить индекс геометрии по `siteId`: угол 1-1, единичные векторы Bay/Row и размеры по обеим осям. Использовать его для абсолютных координат и поворота RTG/RMG.
- Для RTG/RMG вычислять центр как смещение `positionM` вдоль оси движения плюс середина поперечного размера площадки. Для RMG дополнительно сформировать две линии рельсов по `railInsetM` на полную длину площадки.
- Для портальных кранов преобразовать координату Point из CRS QGIS в локальную сцену и вычислить поворот стрелы из геодезического азимута. Передать в объект `model`, `scale` и `color`.
- Учесть фактические корпуса кранов и рельсы при расчёте границ сцены, но не считать выход RTG/RMG за площадку ошибкой.

## Отрисовка и взаимодействие

  - добавить `craneRmg` с рельсовыми тележками;
  - рисовать линии рельсов RMG отдельным проходом после площадок/инфраструктуры и до контейнеров/корпусов кранов;
  - расширить `equipmentBounds`, hit-test и рамку выделения с учётом масштаба.
- В [`src/DataProcessors/d3_v4/Forms/Форма/Module.bsl`](src/DataProcessors/d3_v4/Forms/Форма/Module.bsl) добавить карточки трёх типов: цвет, марка и масштаб для портального; площадка, ось и позиция для RTG/RMG; отступ рельсов для RMG.
